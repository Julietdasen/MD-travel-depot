## 3. 已完成的实例生成工作

### 3.1 Profile 划分

目前使用六类任务实例 profile：

- `balanced`：机器人、任务和资源分布均衡。
- `process_scarce`：处理能力紧张，适合测试机器人处理时间约束。
- `transport_bottleneck`：运输时间成为主要瓶颈。
- `dependency_deep`：任务前置依赖较深。
- `mixed_hard`：混合多种困难因素。
- `scale_medium`：中等规模，用于神经推理和延迟测试。

profile smoke check 为每类 profile 生成 5 个 seed（`81000`--`81004`），覆盖 train/development/test 的任务和机器人规模。检查内容是初始合法动作数量和枚举时间，不等价于完整最优轨迹求解。

### 3.2 Smoke check 结果

| Profile | 合法动作数（最小/中位/最大） | 枚举时间中位/最大（ms） |
|---|---:|---:|
| balanced | 64 / 129 / 740 | 2.25 / 199.13 |
| process_scarce | 27 / 34 / 90 | 0.45 / 1.13 |
| transport_bottleneck | 5 / 11 / 41 | 0.30 / 0.63 |
| dependency_deep | 25 / 25 / 38 | 0.34 / 0.52 |
| mixed_hard | 30 / 92 / 216 | 2.78 / 10.90 |
| scale_medium | 228 / 457 / 2518 | 373.38 / 14702.52 |

重要结论：旧的 24--96 合法动作过滤条件不能全局使用，会系统性排除 `balanced`、`transport_bottleneck` 和 `scale_medium` 样本。后续报告应按 profile 和动作数量分桶统计。`scale_medium` 的完整 continuation 标注在 Mac CPU 上成本较高，应采用抽样或时间限制。

对应报告：`reports/md_instance_profile_smoke_2026-09-10.md`。

## 4. 已完成的实验与结果

### 4.1 Profile pilot 与贪心基线

每个 profile 都有 train/development/test 划分，并记录了合法动作和 exact label 覆盖情况。贪心基线在 pilot 样本中全部完成（每个 profile、每个基线均为 `4/4` 成功）。已有基线包括：

- `greedy_distance`
- `greedy_eta`
- `greedy_unlock`

报告：`reports/md_profile_pilot_2026-09-11/final_report.md`。

### 4.2 Sequential Prefix Decoder

该实验是原型验证，不接入生产调度。当前报告中的 Beam-16 结果：

| 指标 | Prefix-zero | Prefix |
|---|---:|---:|
| Top-1 optimal | 0.1944 | 0.2778 |
| Mean regret | 7.7222 | 11.3056 |
| 最大 p95 CPU 时间 | - | 17.557 ms |

已验证：输出动作合法、exact-label 与 mask 覆盖率为 100%、checkpoint/gradient 检查通过，prefix 会改变 logits。由于严格的 mean-regret 改善门槛未满足，暂不接入生产调度。

报告：`reports/md_prefix_autoregressive_pilot_2026-09-10/final_report.md`。

### 4.3 Rich-state Prefix Train/Validate

该包的结论是 `rich_prefix_not_supported_for_confirmation`。Prefix 相对 Prefix-zero 的 top-1 下降 `0.1667`，mean regret 增加 `3.1250`，因此只作为开发验证，不作为确认结果或生产模型。

报告：`reports/md_rich_prefix_train_validate_2026-09-10/final_report.md`。

## 5. 复现建议

从 `Sadcher/` 目录执行：

```bash
uv sync
uv run python experiments/md_profile_pilot.py
uv run python experiments/md_prefix_autoregressive_pilot.py
```

如只需检查 profile 生成、合法动作和形状兼容性，优先运行对应的 smoke/test 用例：

```bash
uv run pytest tests/test_md_instance_profiles.py tests/test_md_policy_smoke.py
```

训练 C0 或重新生成大规模 exact labels 前，先确认机器存在可见的 `cuda:0`，并核对磁盘空间。`scale_medium` 不建议在 Mac CPU 上进行全量 continuation 枚举。

## 6. 下一位接手者的工作顺序

1. 先运行 profile smoke check，确认 profile、动作计数和合法性没有回归。
2. 按 profile 和动作数量分桶建立统一评测集，不要恢复全局 24--96 过滤。
3. 在 GPU 机器上重新运行 C0 训练和独立 test；当前 CPU 会直接被训练入口拒绝。
4. 只有在 prefix decoder 同时满足 top-1、mean-regret 和延迟门槛后，才考虑接入生产 scheduler。
5. 新生成的数据、日志和权重放入既有 `reports/` 目录结构，并同步增加同日期的交接说明。
